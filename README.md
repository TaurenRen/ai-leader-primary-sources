# ai-leader-primary-sources

把"听说某大牛说过"变成"打开原帖能核实的确切原话"——一个采集国内外 AI 头部研究者一手发言源的 Agent Skill。

## 解决什么问题

写 AI 内容最常见窘境：热点刷屏时，满屏都是第二手转述。你想引 Karpathy 的原话，搜到的却是三层加工后的中文转述，源头链接、时间戳、原话语气全部丢失。

这个技能给 Agent（Claude Code / WorkBuddy 等 Skill 运行环境）一套**定人定源 → 锁时间窗抓取 → 逐字抽取 → 判定可否截图**的固定流程，产出可以直接进文章的素材包。

## 快速开始

把 `SKILL.md` 放进你的技能目录即可：

```bash
# Claude Code 用户
npx skills add TaurenRen/ai-leader-primary-sources
# 或手动复制
git clone https://github.com/TaurenRen/ai-leader-primary-sources.git
cp ai-leader-primary-sources/SKILL.md ~/.claude/skills/ai-leader-primary-sources/
```

然后对 Agent 说："看看 Karpathy 最近一周说了什么，给我能引用的原话"。

## 命令行工具：两条命令，把原话拿到手

不装 Skill 也能用。`scripts/fetch_x.py` 只依赖 Python 标准库：

```bash
python fetch_x.py https://x.com/karpathy/status/2105819303471976479
```

它会按顺序做三件事，并把结果拼成一条可以直接进稿的素材笔记：

1. 跑官方 oembed —— 确认这条推存在、作者是谁、哪天发的
2. 跑第三方镜像 fxtwitter —— 取回**逐字全文** + 发布时间 + 五项互动数据
3. 对比两次结果 —— 官方接口会把长推截断，脚本明确告诉你截了多少字符

第 3 步是这个脚本存在的理由。实测一条 1816 字符的长推，官方 oembed 只给了 346 字符，后面 1470 字符是省略号。**拿到 HTTP 200 不等于拿到了全文**——很多人就是在这一步，替原作者把后半句补上了。

```bash
python fetch_x.py <url> -o research/06-primary-sources.md   # 落盘
```

## 目录结构

| 路径 | 内容 |
|---|---|
| `SKILL.md` | 技能主文件：采集流程、输出格式、硬规则 |
| `scripts/fetch_x.py` | **取 X/Twitter 原推全文**的命令行工具，纯标准库，输出可直接进稿的素材笔记 |
| `scripts/ima_upload_cos.py` | （可选）把采集结果同步到腾讯 ima 知识库的上传脚本，含 COS 签名踩坑记录 |

## 方法说明

三个核心设计，比"会搜索"多一层：

1. **先定人定源，再搜索。** 海外研究者的首发地在 X，国内研究者在微博/公众号——先查对渠道，才不会被二手中转站喂旧消息。
2. **每条素材必填「我的加工」。** 只搬运原话没有价值；素材的价值在于你把它接回到读者的具体麻烦上。这是必填项，不是可选项。
3. **可截图化判定。** 问一句"这张图脱离我的文章单独发朋友圈，别人看得懂吗"——不成立就做引文卡片补背景，而不是硬截。

## 局限与边界

一个不告诉你局限在哪的技能，不值得信任：

- **X/Twitter 直抓常被拦**。降级链（原帖 → 镜像 → 媒体转引 → 转述稿）能提高命中率，但可靠性逐级下降，技能只要求"标注可靠性"，不保证抓到。
- **`fetch_x.py` 依赖第三方镜像 fxtwitter**。它今天能用，不代表下个月还在。镜像挂掉时脚本会明确报错并退回第 1 步，那时你拿到的是被截断的片段——只能当存在性证明，不能当引用源。
- **互动数据是快照**。`views`/`likes` 这类数字每秒都在变，引用时必须写明抓取时刻。实测同一条推在 15 分钟内浏览数从 7,550,816 涨到 7,551,495，中间差 679。
- **不解决版权**。引用原话通常没问题，整段搬运他人长文需要授权——技能里是红线规则，但执行靠人。
- **不追实时**。超 30 天的观点按"背景"处理，本技能不做舆情监控。
- **中文输出为主**。输出格式与规则按中文内容生产场景设计，英文场景需自行调整。
